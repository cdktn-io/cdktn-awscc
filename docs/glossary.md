# Glossary — bridge vocabulary

One definition per term, for `bridge-gap-categories.md`, `awscdk-compat-plan.md`,
`iam-policy-decomposition.md` and the cfncompat RFCs. Terms marked ⚠ are ones the older RFCs use
loosely; prefer the definition here.

| Term | Definition | Notes / collisions |
|---|---|---|
| **cdktn** / **CDK Terrain** | The maintained fork of CDKTF (archived upstream Dec 2025) — the toolkit, runtime library (`cdktn`), CLI, and provider-binding generator. Site: cdktn.io. | Not a synonym for the bridge. RFC 003 uses "CDK Terrain (CDKTN)" for the *project/steward*; RFC 000/002 use "CDK Terrain" to mean *the party that owns the fill-in*. Both are fine; never use it for the synthesis backend itself. |
| **awscc** / **terraform-provider-awscc** | AWS's Cloud-Control-backed Terraform provider (`awscc_*` resources), generated from the same CloudFormation registry schemas as CFN L1 — which is why its shapes match. Version pin lives in `schemas/PROVIDER_VERSION` (1.98.0 at time of writing; 1.99.0 bump in flight). | The *thing the bindings bind*. Distinct from `terraform-provider-aws` (hand-authored, diverging shapes — the fallback provider). |
| **@cdktn/awscc** | The published jsii package of awscc bindings in the aws-cdk-lib L1 *shape*: one submodule per CFN service, `Cc`-prefixed classes (`aws_ec2.CcVPC`), `*Props`, nested `*Property` types. Ships the generated oracles (`CFN_PROPERTY_NAME_MAP`, `CFN_ATTRIBUTE_NAME_MAP`, Ref table, `CfnTypeIndex`). | npm `@cdktn/awscc`; PyPI `cdktn-awscc`. |
| **cdktn-awscc** | The repo (`cdktn-io/cdktn-awscc`) containing that package *and* its generator. Used as an **owner label** in gap tables to mean "generated knowledge, emitted by codegen". | ⚠ Ambiguous between repo, package, and owner-of-gaps. Write `@cdktn/awscc` for the package, `awscc2cdk` for the generator, `cdktn-awscc` for the repo/owner. |
| **awscc2cdk** | The generator inside `cdktn-awscc` (`tools/awscc2cdk/`) that reads the awscc provider schema + `@aws-cdk/aws-service-spec` and emits `generated/`. | |
| **cfncompat** / **terraform-provider-cfncompat** | Our Terraform/OpenTofu provider supplying apply-time CloudFormation semantics: 17 `provider::cfncompat::*` functions, 2 data sources, `cfncompat_custom_resource`. Registry `cdktn-io/cfncompat`. | Used as an **owner label** for gaps that need a running provider. Holds no CFN schema. |
| **the seam** | The AWS-owned interface boundary inside `aws-cdk-lib`: exactly **two new interfaces** (`IReferenceResolver`, `IIntrinsicResolver`) in `core/lib/resolvable.ts` **plus two virtual `Stack` getters** (`referenceResolver`, `tokenResolver`), with the existing CFN behaviour as the default implementation. Reuses three already-public seams unchanged (`ITokenResolver`, `IFragmentConcatenator`, `IStackSynthesizer`). | RFC 002 §1–§2. ⚠ "the seam" is also used loosely in the PRD for the whole pluggable-backend idea; keep the narrow meaning. |
| **seam RFC** | The *public AWS CDK* RFC that will define the above. Not yet published; several of our decisions are explicitly gated on it. | Distinct from cfncompat RFC 002, which is our *proposal* for it. |
| **synthesis backend** | The cdktn-side implementation that replaces CloudFormation template emission: the seam implementations (`TerraformReferenceResolver`, `TerraformIntrinsicResolver`, `TerraformTokenResolver`, `TerraformConcat`), the stack synthesizer, and the artifact/manifest emission. Used as an **owner label** for gaps that are neither generated knowledge nor provider surface. | RFC 002 calls the package `@cdktn/aws-cdk-terraform-provider`; whether it stays a separate package or merges into `@cdktn/awscc` is an open decision. |
| **renderer** / **AwsccL1Renderer** | Specifically the component of the synthesis backend that walks `CfnElement`s and emits `{resource: {awscc_*: {...}}}`: type routing, key translation, `depends_on`, 1:N expansion, `count`. A *part of* the synthesis backend, not a synonym for it. | ⚠ RFC 002 §3 sometimes says "the renderer" where it means the whole Terrain side. |
| **bridge** | Umbrella term for the whole aws-cdk-lib-L2 → Terraform pathway: seam implementations + renderer + `@cdktn/awscc` bindings and maps + cfncompat wiring. Use it only when *all* of that is meant; otherwise name the owner. | ⚠ The most-overloaded term in our docs. Never use "bridge" in an owner column. |
| **keystone** / **deferral keystone** | The reference problem — a `CfnReference` *is* a CFN object before any resolver runs — and its solution: **deferral**, changing only the same-stack `else` branch of `CfnReference.resolve()` to consult `Stack.of(context.scope).referenceResolver`, while keeping the construction-time baked value. | Project-specific coinage bound to this ONE mechanism — never a generic "important piece". No collision. Consequence worth naming: because the design **retains aws-cdk-lib's own synthesis pipeline**, `prepareApp`/`findTransitiveDeps` still run, so construct-tree dependencies arrive already reified — the gap that forced TerraConstructs' `TerraformDependencyAspect` does not exist here. |
| **polyfill** | A gap-filling *mechanism*, applied per pillar wherever a gap category lands: cfncompat functions / data sources / protocol resources for apply-time CFN semantics; the `aws-provider` **fallback** route for awscc resource gaps; renderer idioms (`locals`, folding, `count`-last-resort) for synth-time template features. The gap's category + owner (`bridge-gap-categories.md` §§1–5) determine which form applies. | Originally coined for cfncompat's deploy-time capabilities (RFC 002 §3/§7.1) and grown since. cfncompat-side polyfills are reached only through a *registered* capability (`IIntrinsicResolver.requireCapability`), never implicitly. |
| **oracle / generated oracle** | Our shorthand ("spelling oracles") for the four generated lookup artifacts whose content cannot be derived mechanically: `CFN_PROPERTY_NAME_MAP`, `CFN_ATTRIBUTE_NAME_MAP`, the Ref table, and `CfnTypeIndex`'s generated entries. | "Oracle" = generated truth; contrast the curated rows below. Each artifact has its own doc/row where behaviour matters — this term only names the family. |
| **CfnTypeIndex** | The single machine-readable **router** from CFN type to render target: generated `TF_TYPE`/`BINDING` entries for all awscc-matched types **plus** curated OVERRIDE entries (`kind ∈ aws-provider / cfncompat / decompose`) for the gaps. One lookup, three outcomes: generated → render awscc; override → render the fallback/decomposition target; absent → hard synth-time error with an actionable message. | The one artifact that is deliberately *both* oracle (generated entries) and curated (overrides). Design: PR #4 prompt in `bridge-gap-categories.md` §1. |
| **decomposition table** | Curated 1:N mapping for CFN types with no single Terraform counterpart — today one entry: `AWS::IAM::Policy` → N × `awscc_iam_{role,user,group}_policy`. The table asserts the *targets*; the renderer owns the expansion algorithm, child-id scheme, and dependency propagation (PR #6). | Own doc: `iam-policy-decomposition.md`. Reached via a `decompose` OVERRIDE in CfnTypeIndex. |
| **meta-property equivalence table** | Curated per-resource semantic equivalents for CFN resource attributes (`DeletionPolicy: Snapshot` → `skip_final_snapshot`/`final_snapshot_identifier`, `CreationPolicy`, `UpdatePolicy`). | Plan §8 spike deliverable (`spike-meta-properties.md`); a differentiator — prior art drops all of these silently. |
| **curated table** | Umbrella for any hand-asserted mapping the registry does not encode: the decomposition table, the meta-property equivalence table, and CfnTypeIndex's OVERRIDE entries. Must never be presented as generated truth. | `bridge-gap-categories.md` §4. Prefer naming the specific table; use the umbrella only for the visibility rule. |
| **fallback** | The `aws-provider` OVERRIDE route in CfnTypeIndex: rendering a CFN type awscc lacks onto a `terraform-provider-aws` resource. A polyfill mechanism at the provider pillar — selected by the router, executed by the renderer; the `aws` provider block is emitted per-stack on first use. | Distinct from cfncompat polyfills (apply-time semantics) and from **decomposition** (1:N onto awscc). |
| **TerraConstructs (tcons)** | Prior art: an aws-cdk-L2 fork onto `terraform-provider-aws` with no `aws-cdk-lib` dependency. Cited as an existence proof of the mechanism and as the cost argument against forking. | Never a dependency; only evidence. |
