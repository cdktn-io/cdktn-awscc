The generation pipeline

One pass, two inputs: the terraform provider schema supplies shape and spelling; the CFN service spec supplies names. Everything downstream is a pure function of these.

Worked example: awscc_ec2_vpc end to end (flag on)

The two inputs, side by side — note the spellings each side owns:

// schemas/schema.json → resource_schemas["awscc_ec2_vpc"].block.attributes  (terraform world)
cidr_block  cidr_block_associations  default_network_acl  default_security_group
enable_dns_hostnames  enable_dns_support  id  instance_tenancy  ipv_4_ipam_pool_id

  egress_only_internet_gateway_exclusion  elastic_file_system_exclusion  mode  …

// @aws-cdk/aws-service-spec → resource "AWS::EC2::VPC"  (CFN world)
CidrBlock  EnableDnsHostnames  EnableDnsSupport  InstanceTenancy  Ipv4IpamPoolId
Ipv4NetmaskLength  Tags  VpcEncryptionControl
// TypeDefinition "VpcEncryptionControl":
  EgressOnlyInternetGatewayExclusion  ElasticFileSystemExclusion  Mode  VpcId  State  …

① planResources() — the resource-level join. cfnTypeFor pairs the two worlds with normalizeKey (s.toLowerCase().replace(/[^a-z0-9]/g,"")): AWS::EC2::VPC becomes the join key ec2.vpc, and awscc_ec2_vpc becomes ec2.vpc too — underscores and case are exactly the noise the two sides disagree on, so the key strips both. 1,493 of 1,494 awscc resources find their CFN type this way (the 85.5%-coverage matched set), each producing one:

// PlannedResource — the ×1,494 loop's unit of work
{ awsccName: "awscc_ec2_vpc", cfnType: "AWS::EC2::VPC",
  moduleDir: "aws-ec2", moduleSymbol: "aws_ec2", cfnResourceName: "VPC" }  // → class CcVPC

② The one that doesn't match — fallbackPlan. awscc_datasync_storage_system has no CFN spec entry (the type was retired from CloudFormation; the provider still ships it). fallbackPlan derives everything from the terraform name alone: strip awscc_, first segment is the service (datasync → module aws-datasync), the rest PascalCases to the class name (storage_system → CcStorageSystem) — and cfnType is set to "", which switches off everything CFN-joined downstream: no definition-name recovery (every nested type gets a path-derived name), and no CFN_PROPERTY_NAME_MAP even with the flag on (buildResourceCfnPropertyMap returns empty for cfnType: "", and an empty map emits no static). The resource still generates fully — it just has no CFN spellings to offer.

③ parseResourceAttributes() — shape extraction. Input: the resource's terraform schema block above. Output: the flat attribute list (camelCased prop names paired with their schema spellings) plus structs[path] — one Struct per nested object type, carrying a throwaway placeholder name and its real terraform attribute path from the resource root. The path is the join key everything later uses:

Struct { name: "temp1" /* renamed later */, path: ["vpc_encryption_control"],
         attributes: [ egressOnlyInternetGatewayExclusion ↔ egress_only_internet_gateway_exclusion, … ] }

④ cfn-recovery — the type-level join. resolveDefinitionName(db, "AWS::EC2::VPC", ["vpc_encryption_control"]) walks the CFN property tree matching each path segment by the same normalizeKey: vpcencryptioncontrol hits the CFN property VpcEncryptionControl, which is object-typed → the recovered definition name. After dedupe and allocation (§2) that becomes the emitted type CcVPC.VpcEncryptionControlProperty — the same name aws-cdk-lib derives, which is the shape-parity contract.

⑤ Flag on — the property-level join. buildResourceCfnPropertyMap replays the same walk per level via resolvePropertiesAtPath, then joins attributes to CFN property names by normalizeKey: ipv_4_ipam_pool_id → key ipv4ipampoolid → Ipv4IpamPoolId. Six of the fourteen top-level attributes find no CFN counterpart and are skipped — the real "no CFN counterpart" exit, visible right here: id, vpc_id, default_network_acl, default_security_group, cidr_block_associations, ipv_6_cidr_blocks are awscc's read-only computed attributes, which CFN models as attributes, not Properties. The emitted static therefore maps exactly what has a CFN spelling and nothing else.

Naming: one path in, one grammar-conforming name out

Every nested type name ends in Property (the NAME_GRAMMAR contract). Three stages decide the base, and every comparison along the way is case-insensitive (collisionKey) — the Go/C# one-file-per-type constraint that PR #2 exists for.

How the catalog maps to the diagrams. Each row is one route through the two figures above. In the pipeline figure (§1), every row happens inside the same two boxes — dedupeDefinitionNames → propertyTypeNamesForResource — on the ×1,494 row; the catalog is that pair of boxes opened up. In the decision-flow figure (§2), a row's chip names the branch it takes: recovered rows exit stage 1 on the amber edge and reach the teal terminal; leaf fallback rows exit stage 1 on the gray edge; dedupe and ci collision rows are the two ways into the blue full-path terminal (cleared in stage 2, or re-derived in stage 3's cluster); edge rows are the dashed red boxes and guards. The outcome column is the emitted TypeScript identifier: the nested-type interface declared inside the resource class's namespace in its generated module file — e.g. CcVPC.VpcEncryptionControlProperty in generated/aws-ec2/vpc.ts, or CcApplication.MonitoringHaClusterPrometheusExporterProperty in generated/aws-applicationinsights/application.ts. That one name then seeds everything derived from it in the same file: the exported mapper functions (ccApplication…PropertyToTerraform/ToHclTerraform), the …PropertyOutputReference class, and — via jsii-pacmak — the per-type file names in Go/C#, which is why case-insensitive uniqueness of this identifier is the whole ballgame.

Why stage 2 exists (the reviewer's catch): d9dd03d's case-insensitive union-find fixed the Go build but sent same-named recovered pairs to the numeric-suffix tie-break — OpenIdConnectConfigProperty2 and 15 siblings, all violating the grammar that every property type name ends in Property. Moving the case-insensitive comparison upstream into dedupeDefinitionNames clears the duplicate before allocation, so the loser falls back to its grammar-conforming full-path name instead. The at-risk-first ordering is the subtle part: the occurrence whose fallback would itself collide with the recovered spelling (a top-level attribute, whose full path is its leaf) is exactly the one that must keep the recovered name.

The CFN property-name map (PR #3)

Flag on (emitCfnPropertyMap), each matched resource gets one flat, jsii-visible static: CFN PascalCase name → terraform attribute name, merged across the whole property tree.

// generated (flag on) — lands in the .jsii assembly; the *ToTerraform functions do not
export class CcVPC extends cdktn.TerraformResource {
  public static readonly tfResourceType = "awscc_ec2_vpc";
  public static readonly CFN_PROPERTY_NAME_MAP: { [cfnName: string]: string } = {
    "EgressOnlyInternetGatewayExclusion": "egress_only_internet_gateway_exclusion",  // nested
    "Ipv4IpamPoolId": "ipv_4_ipam_pool_id",  // the non-derivable case
    …
  };

The build walks levels — the resource root (path: []) plus every struct — and joins each level's terraform attributes to the CFN properties at the same path. Both sides of the join use normalizeKey (strip underscores, lowercase), the same join logic cfn-recovery uses to recover definition names, now exposed as resolvePropertiesAtPath. Four exits keep the map honest rather than complete:

  • Unmatched resource (cfnType: "", the fallbackPlan case) → empty map → no static emitted at all; output byte-identical to flag-off.
  • Path isn't an object-typed CFN property (primitive, or awscc diverged) → level skipped.
  • Attribute has no CFN counterpart at its level (7,309 across the schema) → entry skipped — absence in the map means "no CFN spelling exists," never a guess.
  • Same CFN name seen twice → first-writer-wins, root-first — a determinism net the pre-study proved is never taken (0 conflicts in 30,674 pairs).
4

Sequences

Two moments matter: generation time (once per provider version, offline) and synth time (every consumer run). The map exists so a third actor — the Phase-2 bridge — can join at synth time without the mappers.

Reading the atlas as one argument: §2 guarantees every emitted type name is deterministic, grammar-conforming, and case-insensitively unique per module (the Go/C# constraint, gated by iter5.go-case.test.ts on the committed tree). §3 rides the same CFN join to publish the one artifact the bridge needs at synth time. §4 shows why it must be a static on the class: the mapper functions in the left lane of the synth sequence exist only in the embedded JavaScript — the map is the only spelling oracle that survives into Python, Java, .NET, and Go.
